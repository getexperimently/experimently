Experimently {{ .Chart.AppVersion }} ({{ .Values.profile }} profile) is installing as release {{ .Release.Name }}.

1. Wait for the API. Its `migrate` init container creates or upgrades the schema first:

     kubectl rollout status deployment/{{ include "experimently.fullname" . }}-api -n {{ .Release.Namespace }}

   If a pod stays in Init, read the bootstrap's log:

     kubectl logs -n {{ .Release.Namespace }} deploy/{{ include "experimently.fullname" . }}-api -c migrate

2. Check that the API answers on your public host, not only its health probe
   (probes are exempt from the Host check, so they stay green when the host is wrong):

     helm test {{ .Release.Name }} -n {{ .Release.Namespace }}
{{- if .Values.ingress.enabled }}
     curl -s -o /dev/null -w '%{http_code}\n' {{ .Values.publicBaseUrl }}/api/v1/experiments/    # expect 401
{{- else }}

   The Ingress is disabled. Route {{ .Values.publicBaseUrl }} yourself: /api, /ws and /health to
   service/{{ include "experimently.fullname" . }}-api:8000, everything else to service/{{ include "experimently.fullname" . }}-web:8080,
   passing the original Host header.
{{- end }}

3. Sign in at {{ .Values.publicBaseUrl }} as {{ .Values.firstSuperuser }} with the password from your Secret.
   That password is used only when the first administrator is created; changing it later does nothing.
