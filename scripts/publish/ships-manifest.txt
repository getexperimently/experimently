# The positive half of the publication gate: every top-level entry, and every
# `docs/` subdirectory, that MAY appear in the exported history.
#
# scripts/publish/exclude-paths.txt says what must be REMOVED, and it can only
# ever check what someone remembered to write in it. That is how
# `docs/go-to-market` stayed in the publishable history for months with the
# "excluded paths absent from history" sweep passing the whole time -- and how
# `TRANSITION_TO_COMMERCIAL.md`, `docs/deployment/MARKETING_WEBSITE_GUIDE.md`
# and `ee-manifest.txt` were still there after the first attempt to fix it. An
# omission from a deny-list is unfalsifiable: nothing can report the entry that
# was never written.
#
# This file inverts the question. export.sh reduces the rewritten history to
# its top-level entries plus its `docs/` subdirectories and FAILS on anything
# not listed here, so a new internal directory has to be argued onto this list
# rather than silently passing.
#
# WHAT THIS DOES NOT CATCH: a single internal file dropped inside a directory
# that legitimately ships. `docs/deployment/MARKETING_WEBSITE_GUIDE.md` was
# exactly that shape -- `docs/deployment` ships, so only the deny-list entry
# removes it. This gate catches the common shape (a new top-level entry or a
# new `docs/` subdirectory); it is not a substitute for reading the deny-list.
#
# Entries are the state of `main`'s history as measured, not as remembered:
# regenerate the candidate list with
#
#   git rev-list --objects main | awk 'NF>1{print $2}' | sort -u
#
# and reduce it the way export.sh does. One entry per line; `#` comments and
# blank lines ignored. A trailing comment on an entry line is allowed.
