Create and apply a database migration safely.

Generate a new Alembic migration, review it for accuracy, and apply it to the database.

Arguments: $ARGUMENTS (required - migration description)

Steps to execute:
1. Set required environment variables: POSTGRES_DB=experimentation and POSTGRES_SCHEMA=experimentation
2. Find the heads: python -m alembic -c backend/app/db/alembic.ini heads
   A full checkout has TWO — the core chain and the `modules` branch — so a bare
   --autogenerate fails with "Multiple heads are present".
3. Generate migration naming the head it extends:
   - a core change: alembic revision --autogenerate --head <core head id> -m "$ARGUMENTS"
   - a module's:    alembic revision --autogenerate --head modules@head -m "$ARGUMENTS"
     (that one lands in modules/backend/app/db/migrations/versions/)
4. CRITICAL: Review the generated migration file carefully for:
   - Correct down_revision pointing to the right previous migration ID
   - The file is in the right versions directory for its head
   - Accurate schema changes matching your model changes
   - Proper table names with schema prefix
   - No unintended drops or alterations
5. Apply the migration: python -m alembic -c backend/app/db/alembic.ini upgrade heads
   (`heads`, plural: `upgrade head` fails with "Multiple head revisions are present")
6. Verify successful application with: python -m alembic -c backend/app/db/alembic.ini current
   (one row per head, so two lines on a full checkout)
7. Display migration history with: python -m alembic -c backend/app/db/alembic.ini history --verbose | head -20

Safety checks:
- Always verify down_revision chain integrity
- Two heads is the steady state, not an error: NEVER run `alembic merge` on them.
  The merge file lands in the core versions directory and names the module head in
  its down_revision, which a core checkout does not have.
- Review autogenerated code for complex changes
- Ensure schema is set correctly in all operations

Example usage:
- /migration "add user preferences table"
- /migration "add index on experiment_assignments user_id"
