# Runtime dependencies the modules add on top of backend/requirements.txt.
#
# Only the full profile installs these: backend/Dockerfile's `full` stage
# (from modules/requirements.lock, hashed), the `full-build` and
# `modules-tests` CI jobs, and _platform.yml with `profile: full`. A core
# checkout has no modules/ directory and therefore none of these packages.
#
# Nothing under backend/ imports any of them; every module that does guards
# the import (`try: import pymysql / except ImportError: pymysql = None`), so
# a full checkout still imports cleanly without them — it just cannot connect.
#
# Keep this list to what the modules import at RUNTIME. Test-only and
# infrastructure tooling (pytest, moto, aws-cdk-lib, pyspark for the Glue
# jobs) stays in backend/requirements.txt, which CI installs alongside.
#
# After editing, regenerate the lock: `make lock` (or `make lock-modules`),
# then commit modules/requirements.lock. `make lock-check` /
# scripts/check_requirements_lock.py fail when the two drift.
